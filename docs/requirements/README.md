## Requirement writing conventions

- Give each approved requirement a stable ID, such as `FR-001` or `NFR-001`.
- Write requirements so they can be tested and have one clear interpretation.
- Record priority, rationale, and acceptance criteria where applicable.
- Mark assumptions and unresolved questions instead of treating them as agreed requirements.
- Keep changes traceable through Git history.
